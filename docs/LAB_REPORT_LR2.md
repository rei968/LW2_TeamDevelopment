## 🎯 1. Мета та завдання лабораторної роботи

### Мета роботи:
Оволодіти практичними навичками організації командної розробки сучасного програмного забезпечення із застосуванням розподіленої системи контролю версій **Git**, вивчити та застосувати модель розгалуження **Git Flow**, засвоїти стандарти повідомлень комітів (Conventional Commits), виконати паралельну реалізацію функціональних модулів у персональних гілках, а також свідомо спровокувати, проаналізувати та розв'язати реальний конфлікт злиття (Merge Conflict) у коді бізнес-логіки.

### Основні завдання:
1. **Ініціалізація та гігієна репозиторію:** Очищення робочого простору від застарілих файлів та фіксація чистісінької бази на гілці `develop`.
2. **Розподіл обов'язків та ролей:** Створення структури гілок `feature/*` для кожного члена команди з чітким розмежуванням зон відповідальності.
3. **Розробка архітектури CineSphere:** Створення модульного веб-додатку з нульовою кількістю сторонніх залежностей (Zero-Dependency Vanilla HTML5/CSS3/ES6 JS + LocalStorage DB).
4. **Створення та злиття користувацького інтерфейсу:** Реалізація вітрини фільмів, карток з hover-ефектами, бейджів форматів та системи скидання пошуку в гілці `feature/zhe-catalog-ui` з подальшим злиттям у `develop`.
5. **Симуляція та вирішення Merge Conflict:**
   - Паралельне внесення несумісних змін у розрахунок знижок у файлі `js/pricing.js` (VIP-знижка 10% від Яріка та групова знижка 15% від Же);
   - Фіксація виникнення конфлікту при злитті гілки `develop` у `feature/zhe-bulk-discount`;
   - Збереження конфліктних маркерів у текстові контрольні точки (Checkpoints);
   - Спільне узгодження та інтеграція обох бізнес-правил в єдиний алгоритм;
   - Завершення коміту злиття та оновлення інтеграційної гілки `develop`.
6. **Забезпечення якості (QA):** Розробка та виконання 21 автоматизованого тесту в автономному браузерному тестовому середовищі `tests.html`.
7. **Автоматизація фіксації результатів:** Створення сценарію PowerShell для зняття знімків екрана (headless Chrome/Edge) та генерація повного пакета графічних і текстових доказів.

## 🏗️ 2. Архітектура та стек технологій проєкту «CineSphere»

Додаток побудовано за принципом багатошарової модульної архітектури без використання важких сторонніх фреймворків чи зовнішніх бібліотек (Zero Dependencies), що гарантує 100% працездатність у повністю автономному (offline) лабораторному середовищі:

```text
CineSphere Client Architecture:
┌─────────────────────────────────────────────────────────────────┐
│                     Презентаційний шар (UI)                     │
│   index.html | css/variables.css, main.css, components/*.css   │
│   js/ui/catalogView.js | js/ui/hallView.js | js/ui/modalView.js │
└───────────────────────────────┬─────────────────────────────────┘
                                │ Події користувача / Рендеринг
┌───────────────────────────────▼─────────────────────────────────┐
│                  Шар реактивного стану (State)                  │
│   js/state.js — CineSphereStateStore (PubSub шина подій)        │
└───────────────────────────────┬─────────────────────────────────┘
                                │ Виклики бізнес-логіки
┌───────────────────────────────▼─────────────────────────────────┐
│               Шар предметної логіки (Domain Logic)              │
│   js/pricing.js — Розрахунок цін, націнок, знижок та промокодів │
│   js/booking.js — Матриця залу, валідація, захист від колізій   │
└───────────────────────────────┬─────────────────────────────────┘
                                │ Читання / Запис даних
┌───────────────────────────────▼─────────────────────────────────┐
│                   Шар персистентності (Storage)                 │
│   js/db.js — Клієнтська БД з автопосівом (LocalStorage API)     │
└─────────────────────────────────────────────────────────────────┘
```

### Основні модулі системи:
- **`js/db.js`**: Реалізує шар збереження даних на базі Web Storage API (`localStorage`) із префіксом простору імен `cinesphere_*_v1`. Забезпечує самовідновлення при пошкодженні даних, попередній посів (4 фільми з векторними SVG-постерами, 2 кінозали з конфігурацією місць, 6 сеансів та початкові броні).
- **`js/state.js`**: Реактивне сховище стану додатка на патерні Observer/PubSub, що синхронізує активний сеанс, вибір місць (із жорстким лімітом до 6 квитків на клієнта) та навігаційні переходи.
- **`js/pricing.js`**: Модуль розрахунку ціноутворення. Обчислює націнки на категорії крісел (Standard, VIP +50 грн, Дивани +100 грн), студентські знижки (-15%), обробку промокодів (`STUDENT10`, `CINE20`), а також об'єднану логіку після розв'язання конфлікту (групові та VIP-знижки).
- **`js/booking.js`**: Транзакційний контролер бронювання. Будує двовимірну матрицю сидінь, перевіряє заповненість полів клієнта (`fullName`, `phone`), генерує унікальні квиткові коди формату `CS-XXXXX` та атомарно блокує спроби повторного викупу зайнятих місць (Double-Booking Prevention).
- **`tests.html`**: Повнофункціональний браузерний тестовий раннер (BDD-стиль: `describe`, `it`, `expect`) із візуальними метриками швидкодії та статусами проходження.

## 💥 5. Практичний сценарій виникнення та вирішення Merge Conflict

Згідно з обов'язковими вимогами лабораторної роботи (Вимога R2 та `docs/GIT_WORKFLOW.md § 4`), команда змоделювала та успішно розв'язала реальний конфлікт одночасного редагування спільного коду бізнес-логіки.

### 📍 Локалізація конфлікту:
- **Файл:** `js/pricing.js`
- **Функція:** `calculateOrderTotal(params)`
- **Суть колізії:** Два розробники одночасно додали різні бізнес-правила нарахування знижки в одному й тому самому місці функції замість попереднього плейсхолдера `// TODO (Ярік)`.

---

### Етап 1. Зміни першого розробника (Ярік — VIP-знижка)
Ярік у гілці `feature/yarik-vip-discount` реалізував знижку 10% для клієнтів, які обирають крісла підвищеного комфорту:
```javascript
  const hasVipSeats = seats.some(s => s.tier === 'vip');
  if (hasVipSeats) {
    discountRate = 0.10; // Знижка 10% для поціновувачів комфорту (Ярік)
  }
```
Коміт: `f6746c4` (*"feat(pricing): додано знижку 10% на замовлення з VIP-місцями"*).  
Гілка була злита в `develop` через коміт `427544c`.

---

### Етап 2. Зміни другого розробника (Же — Групова знижка)
У той самий час Же у паралельній гілці `feature/zhe-bulk-discount` змінив ті самі рядки, додавши знижку 15% для замовлень великих компаній (від 3 квитків):
```javascript
  if (seats.length >= 3) {
    discountRate = 0.15; // Групова знижка 15% для компаній від 3 осіб (Же)
  }
```
Коміт: `80bcb9d` (*"feat(pricing): додано знижку 15% для замовлень від 3 квитків"*).

### Етап 3. Виникнення конфлікту під час злиття
Перед відкриттям Pull Request розробник Же оновлює свою гілку актуальним кодом з `develop`:

### Етап 5. Узгоджене рішення команди та фінальний код
На спільній нараді команда вирішила **не відкидати жодне з правил**, а об'єднати їх у взаємовигідну систему лояльності за ієрархією пріоритетів (Промокод $\rightarrow$ Студент $\rightarrow$ Компанія $\ge$ 3 осіб $\rightarrow$ VIP-місце):

```javascript
  const upperCode = (promoCode || '').trim().toUpperCase();
  let discountLabel = null;
  const hasVipSeats = seats.some(s => s.tier === 'vip');

  // Об'єднана логіка після вирішення Merge Conflict (docs/GIT_WORKFLOW.md § 4):
  if (upperCode && PROMO_CODES[upperCode]) {
    discountRate = PROMO_CODES[upperCode].discountPercent / 100;
    isPromoValid = true;
    discountLabel = PROMO_CODES[upperCode].label;
  } else if (isStudent) {
    discountRate = 0.15;
    discountLabel = 'Студентська знижка (-15%)';
  } else if (seats.length >= 3) {
    discountRate = 0.15; // Знижка для компаній (від Же)
    discountLabel = 'Групова знижка від 3 квитків (-15%)';
  } else if (hasVipSeats) {
    discountRate = 0.10; // Знижка на VIP (від Яріка)
    discountLabel = 'VIP-знижка (-10%)';
  }
```
